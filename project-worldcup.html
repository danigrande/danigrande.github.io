Worldcup Pool App — Agente Mundial

An AI-powered World Cup prediction pool with a seven-personality chatbot, real-time scoring, and 14-language banter — built for friend groups to compete, trash-talk, and celebrate together.

Role: Product Manager & Sole Builder Timeline: 2026 Status: Live prototype (web + TestFlight)

Every World Cup, millions of friend groups run prediction pools on spreadsheets and WhatsApp. Someone has to calculate the points by hand, predictions live across scattered chats, and the whole thing goes quiet after matchday one.

I built the alternative: a real app for the pool — and gave it a personality. Agente Mundial is an AI chatbot with seven distinct characters that talks trash, summarizes matches, and keeps the group engaged through the entire tournament.

Live prototype. The app runs on the web and on iPhone (TestFlight), with the chatbot's quality pipeline — automated scoring plus human review — running behind every message.

The Problem

Manual score tracking — someone computes the points by hand. No single source of truth — predictions live across spreadsheets and chats. No real-time engagement — the pool goes silent after the first matchday. A generic, impersonal experience — every pool tool looks and feels the same.

The Opportunity

Combine the social ritual of the pool with modern AI to make something sticky and different. A personality-driven chatbot keeps the banter going all tournament. Real-time scoring makes the leaderboard a daily destination. And football fandom is global — transcreation opens 14 languages from day one.

The north star: the ultimate companion for World Cup 2026 — predictions, banter, and AI-generated hype in one place.

Target Users

Friend groups, football fans, and casual bettors who want a fun, low-stakes competition during the World Cup. No gambling — just bragging rights.

Core Differentiator

Agente Mundial — an AI chatbot with seven distinct personalities (Andrés Montes, Josep Pedrerol, Donald Trump, Darth Vader, and more) that delivers trash talk, match summaries, and memes in 14 languages.

Strategic Bets

The chatbot as the core differentiator vs. traditional pool tools. Two prediction modes to serve different preferences. 14-language transcreation for global reach. An automated quality gate to keep AI quality high at scale.

Prediction Engine

All 12 groups (48 teams) plus the knockout rounds through the final. Two modes: Classic (fill everything before the tournament) and Dynamic (predict round by round). Automatic standings, bracket resolution, real-time sync, and honour-roll picks: champion, runner-up, Golden Boot, Golden Ball.

AI Chatbot — Agente Mundial

Seven personalities with unique voices, prompts, and even personality-specific error messages. 14 languages via transcreation. Conversational memory, live web search for match news, RSS monitoring, daily AI-generated tournament summaries, and voice message support.

Leaderboard & El Muro

Real-time point calculation as scores come in. The Pool Wall ("El Muro") shows every player's predictions in one view — the fuel for social competition. Each pool is isolated with its own rules and admins.

Every chatbot message flows through a pipeline built for quality, safety, and cultural fit:

User Message → RAG Memory → Web Search → Personality Prompt → Groq LLM → Judge Eval → Transcreation → Response

The stack

Frontend HTML/CSS/JS Backend Node.js + Express Database MongoDB Atlas LLM Groq Cloud (Llama 3.3 70B) RAG LangChain + vector store Search Tavily Realtime Socket.IO Hosting Vercel + Render Testing Jest + Supertest

No frontend framework
Why: speed of iteration for a solo build; static hosting is free and there's no build step. Trade-off: more manual UI work and no component reuse. Verdict: right call for an MVP; a team would want React.
Groq (Llama 3.3 70B) over OpenAI
Why: far lower latency and cost, with comparable quality for structured tasks. Trade-off: a younger ecosystem. Verdict: correct — inference speed is what makes the chatbot feel real-time.
RAG + web search for memory
Why: a chatbot that forgets the conversation or doesn't know today's results is useless. Trade-off: added latency and architectural complexity. Verdict: essential for quality.
Two prediction modes
Why: some users want set-and-forget; others want to react round by round. Trade-off: double the UI and validation logic. Verdict: correct — it tested well with real users and widened the audience.
Judge + human-in-the-loop
Why: AI content at scale needs a quality gate — every response is scored by a smaller model, and low scores trigger human review. Trade-off: added cost and latency per message. Verdict: critical for a consumer-facing product.
Transcreation over translation
Why: football banter doesn't translate literally; the pipeline adapts humour and idioms culturally across 14 languages. Trade-off: significant upfront investment. Verdict: worth it — nuance is the difference between funny and offensive.

What Informed the Features

Observing how real friend groups run pools — mostly spreadsheets plus WhatsApp. The personalities were chosen for cultural relevance: iconic Spanish football voices alongside universal characters. Two prediction modes came from two real user behaviours: planners and reactors.

Built-in Feedback Loops

In-app feedback with voting, so users prioritise their own requests. Correction detection, so when a user corrects the bot it becomes a reviewable signal. Judge logs, so every AI response is scored and low-scoring ones are flagged for human review.

The product evolved through seven phases, each one usable on its own:

  • Phase 1 — Core pool: accounts, groups, prediction entry, scoring engine, leaderboard
  • Phase 2 — Chatbot v1: Agente Mundial with one personality, English and Spanish
  • Phase 3 — Multi-personality: seven personalities with unique prompts and error handling
  • Phase 4 — Quality pipeline: automated judging, human review, correction detection
  • Phase 5 — Global reach: transcreation pipeline, 14 languages, translated UI
  • Phase 6 — Intelligence layer: conversational memory, web search, RSS monitoring
  • Phase 7 — Metrics & ops: developer dashboard, health monitoring, usage analytics

Beyond the build, I wrote a six-module strategy teardown of the product — the bet, the moat, the margin, the contract, the guardrails, and the pitch — with real numbers: unit economics, defensibility, reliability targets, and regulatory exposure.

Delivery phases

Figures describe the built prototype, as of September 2026.

  • RAG quality is harder than it looks. Chunking, embeddings, and retrieval relevance all needed iteration — and a dedicated evaluation set would have sped that up.
  • Transcreation paid for itself. Non-English users reported far higher satisfaction than with raw machine translation.
  • Judges need calibration. The scoring model disagreed with human reviewers on borderline responses; a rubric with examples helped, but it's an ongoing problem.
  • Personality is fragile. Without careful anchoring, the bot drifts out of character. Character consistency should be tested automatically.
  • Start the quality pipeline earlier. Adding judging and human review after launch created a retrofitting tax. Next time: day one.

The app is live as a prototype. Next up: the feedback-to-PRD agent pipeline (built, pending deployment) and the quality improvements tracked in the chatbot improvement plan.
