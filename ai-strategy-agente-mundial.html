1 The Bet — What We're Building, For Whom, Why Now

Three-Axis Vulnerability Diagnostic M1 · diagnostic.md

Product: Worldcup Pool (Agente Mundial) · Role: Product Manager

Contextual Moat
2/5
Mid-tournament lock-in is near-absolute — stateful leaderboard, social graph, and personalized AI banter mean users can't migrate mid-World Cup. However, pre-tournament switching cost is near-zero. Before the first match, users easily move to a competitor.

Attacker: Fantasy league equivalents, online spreadsheets.
Data Advantage
2/5
The architecture captures a unique signal (social graph + game state → humor), but the moat does not exist yet. You have zero user data at launch — the golden dataset (101 hand-crafted tests) validates the model but does not train it. Fine-tuning is Year 2; it cannot improve this World Cup.

Risk: Competitors have 4 years until the next World Cup to replicate the experience with standard APIs.
Platform Exposure
4/5
Low encroachment risk from Apple/Google/OpenAI — they build horizontal platforms, not culturally specific social apps. The real threat is users hacking together a "good enough" solution inside WhatsApp/Telegram. Score drops from 5 to 4 because self-hosting introduces operational risk: GPU downtime, fixed capacity, no burst scaling.

Top Vulnerabilities

1. Post-Event Churn (Critical): DAU drops ~100% the day after the final. The backend is hardcoded to the 2026 World Cup schedule. No secondary mode exists. "Pivot to La Liga" requires 4–6 weeks of engineering that must happen post-tournament, when attention has peaked.

2. No Data on Day One (High): On June 11, the training dataset is empty. The best version of the product exists for the next tournament, not this one. The self-hosted 8B with engineered prompts clears evals but is not fine-tuned — it cannot be, because there is no user data yet.

3. Self-Hosted Infrastructure Risk (Medium): GPU downtime during a live match kills all bot responses. Capacity is fixed (a single A10G handles ~100 req/s). If 10,000 users trigger the bot during halftime, there is no burst scaling. The fine-tuned model can regress without an operational eval pipeline.

4. Revenue Model Untested (Medium): Assumes 10% conversion at $4.99/group. 3–5% is more realistic for a first-time consumer social app, halving pass revenue and pushing CapEx payback from 18 months toward 36+.

5. LLM Unit Economics (Mitigated, Replaced by Infrastructure Risk #3): API cost scaling is structurally solved by the self-hosted cascade. Fixed GPU cost means marginal cost per bot response is near zero. But the pricing problem has been traded for an infrastructure problem.

2 The Moat — Why It Won't Get Copied in Six Months

Data Flywheel Map M2 · data-flywheel.md

LoopWhat It MeasuresScore
CorrectionDo users fix AI outputs? Is that signal captured and reused?3/5
PreferenceDoes the product learn individual/team preferences over time?3/5
Domain ContextDoes usage in one area improve quality in adjacent areas?2/5
NetworkDoes each new user/team make the product better for everyone?2/5

Total Flywheel Score: 10/20. Weakest loop: Domain Context + Network (tied at 2/5).

Correction Loop — 3/5: three capture mechanisms exist: thumbs up/down with reason (ChatbotFeedback), conversational correction detection (messageHandler.js:69–127), and a HumanReview queue (devDashboard.js:683–848). However, all reuse is manual — a developer must open the queue, submit a verdict, and click "promote". No automated retraining pipeline exists.

Preference Loop — 3/5: static profile fields (likes, dislikes, humor_style) set manually by the user + short-term RAG memory (last 30 messages). No automated fact extraction — if a user says "I hate France" in chat, the bot remembers it via RAG for a few hours but does not permanently update the user's profile. Humor style and personality are set once during onboarding and never adjusted.

Domain Context Loop — 2/5: all flows are unidirectional. News (RSS) and game state (leaderboard) feed into chat, but chat output does not improve news or game domains. RSS uses hardcoded keywords — it does not read group chat to identify which teams a group cares about. Data is fully siloed per group.

Network Loop — 2/5: strong intra-group effects (each new user makes the group better) but zero inter-group effects. 1,000 groups in Argentina and 1,000 in Spain are completely siloed. Fine-tuning will eventually create inter-group effects, but that requires 2,000+ quality entries and a post-tournament deployment — it does not help this World Cup.

Encroachment Threat Assessment

1. Platform Encroachment

Attacker: Meta (WhatsApp) / Apple Intelligence
Vector: native AI agents in default group chats.
Time-to-threat: 1–2 years.
Value at risk: 30–40% — dedicated UI/UX is the defense.

2. Vertical Competitor

Attacker: Sleeper / ESPN / Yahoo Fantasy
Vector: incumbent social fantasy sports adding AI commish.
Time-to-threat: 6–12 months.
Value at risk: 90–100% — existential if target users are already on Sleeper.

3. Adjacent Expansion

Attacker: Telegram Mini-Apps / Bot developers
Vector: frictionless distribution inside existing chat apps.
Time-to-threat: 3–6 months.
Value at risk: 70–80% — attacks the GTM friction of getting 10 friends to download a new app.

90-Day Encroachment Plan: Meta (WhatsApp)

  • Attack vector: your weakest loop is GTM friction — Meta attacks by launching the feature exactly where friend groups already live.
  • Weeks 1–4: Meta rolls out "WhatsApp Sports Bots" powered by Llama 3. Any user types @MetaAI start a World Cup pool and a native leaderboard pins to the chat.
  • Weeks 5–8: one week before the World Cup, the "Alpha" friend tries to get the group on Agente Mundial, but 3 friends complain. They give up and use WhatsApp instead.
  • Weeks 9–12: the tournament is mid-knockout stage. Users are permanently locked into WhatsApp — stateful points and banter history can't migrate mid-tournament.
  • Your defense: hyper-vertical brand safety moat (Meta AI is too polite to be genuinely funny), dedicated UX (chat is a terrible interface for complex stats), and "Sanctuary" positioning (groups want a dedicated app to separate game noise from daily life).

Pricing Model: Admin-Sponsored Group Pass

Free tier: create groups, invite friends, enter predictions, view leaderboard, 4 AI personalities (2 ES + 2 EN), push notifications, daily AI summaries — zero friction. Banner ads shown on leaderboard and chat.

Group Pass ($4.99 one-time per tournament): the group admin pays once. Unlocks all 7 AI personalities, no banner ads, breaking news RSS broadcasts, cosmetics (custom avatars, nickname colors, chat themes, animated effects) for the entire group for ~40 days.

Margins: AI COGS ~$0.30–0.50 per group per tournament → 90–94% gross margin on pass revenue. Blended gross margin including ads: ~55–65%. The $4.99 price point is structurally sound only because the self-hosted cascade caps marginal cost.

Break-Even Analysis

Payback at $27k CapEx: ~5,400 paid groups ($27,000 / $4.99 gross pass rev). At 10% conversion, ~54,000 total groups needed. Self-hosted OpEx ($900–1,700/mo) is covered by ~180–340 paid groups per month on pass revenue alone. The first tournament (40 days) likely breaks even on OpEx but does not recover the full CapEx — that requires 2–3 tournaments or hitting 100k users.

Current state: not implemented. Judge scores exist in AILog + dev dashboard but never shown to users. Thumbs up/down with 1–5 rating is already implemented.

Red-Team Findings

1. Golden dataset too small for statistical significance. 101 tests across 6 categories means the personality dataset (29 tests) can flag a regression but cannot measure it precisely. One failure drops the pass rate by ~3.4pp. Minimum viable size: ~200 tests per category.

2. No latency SLO enforcement. p95 <800ms target exists but latency is only logged to AILog. No alerting, no paging, no dashboard. If the self-hosted GPU degrades during a match, you won't know until users complain.

3. No data freshness gate. The golden dataset is static hand-crafted JSON. No mechanism to automatically add new edge cases from production. The dataset grows only when a developer manually adds cases.

Board Pitch

Thesis: "Personality-driven AI commentary turns a static World Cup prediction pool into a daily social ritual — and the 50-day tournament generates enough data to validate a year-round product before the next major event."

1. Why now. June 1 — 10 days before kickoff. The 2026 World Cup starts June 11. We have a live, tested application with 7 personalities, a Judge on every response, a 101-test golden dataset, and a HITL system ready. The gap is not the product — it's the $27k CapEx to ship monetization and the self-hosted GPU to survive 100k users. Every day of the tournament generates corrections and golden dataset entries that compound the moat.

2. What's defensible. (1) 7 culturally-specific personality anchors with hardcoded catchphrases and forbidden patterns. (2) Golden dataset — 101 curated tests across 14 languages, growing daily via HITL. (3) User corrections — every correction is a labeled data point with full context. (4) Transcreation pipeline — 8 non-Latin scripts with cultural adaptation. (5) Feedback → PRD pipeline via LangFlow. None are un-copyable alone; together they create a 6–12 month head start. The true moat (fine-tuned model) is Year 2.

Key Strategic Change
