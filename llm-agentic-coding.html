Costs of LLMs & Agentic Coding

What it actually costs to build software with AI agents — the setup I use, what the alternatives would have cost, and when running models locally makes sense.

Setup: opencode + DeepSeek V4 Flash Evidence: GrandeSuite Next Also tried: Kilo Code, Antigravity

This is not a page about which model each project uses. It's about how I actually build — the tools, the model choices, and what it all costs.

The headline: I build with opencode running DeepSeek V4 Flash, and for agentic coding its price-to-capability ratio has been unbeatable.

1 How I Build, and What It Costs

My daily driver is opencode with DeepSeek V4 Flash. I used it intensively for about three weeks to build GrandeSuite Next end-to-end — and that token usage is roughly what a single worker would consume over three weeks of work. The whole project came in at a cost that would be hard to match with a frontier model.

Why DeepSeek wins on cost. DeepSeek V4.1 Flash caches far more aggressively than the others: a cache read costs 2% of input with free writes and persists hours–days. Anthropic and OpenAI read at ~10%; Anthropic charges 1.25× for cache writes and its cache expires in 5 minutes, so it caches less in practice. The cache-hit ratios above are estimates — they are what drive the cost. Figures are input + cache read + output + cache writes at September 2026 list rates; on a flat-rate plan like opencode GO, the cash cost is lower still.

I've tried the alternatives — other models, and other IDEs like Visual Studio with Kilo Code, and Antigravity. They work. But on cost, opencode + DeepSeek is in a different league.

2 Cheap vs. Frontier Models

It's noticeable — especially for planning — that frontier models are better. They make fewer mistakes, and that means I lose less time. When a model gets it wrong, I pay for it twice: once to notice, once to fix it.

So the choice depends on the stakes:

  • When failure is cheap, I'd use cheaper models without hesitation. If something breaks and it doesn't matter, why pay more?
  • When correctness matters — or I need to do something complex, fast — the smarter model wins. The fear of shipping something broken, and the need to move quickly on hard problems, makes frontier models worth the premium.

The real cost equation isn't price per million tokens — it's tokens plus the time lost to errors.

3 Local LLMs for Agentic Coding

"Can I just run this on my own machine?" is the question everyone asks. The honest answer depends on what you're doing:

On a personal computer — for agentic coding

An absolute no-go. Small models aren't smart enough to drive an agent, you need roughly double the RAM of the context window (easily a 200k window), and the speed is far too slow to be usable.

Locally, for simple tasks

Yes, definitely. A small LangChain workflow pointed at a local model via Ollama, LM Studio, or MLX works well for simple jobs. And if it needs to run 24/7, you can host it on Vercel connected to HuggingFace — simple, and cheap.

A local server for big models (Kimi K2, GLM 5.1)

Not worth it. Running models that size needs serious hardware and serious money. It only makes sense if you have 30–50 users to spread the cost across.
