How I choose models, control costs, and let AI agents write production code — without losing quality.

There is no single best model — there is a best model for each job at each price point. I run a portfolio: fast and cheap where volume is high, stronger where judgment matters, small and self-hosted where the economics demand it.

And I don't just use models — I use them to build. AI agents wrote the ERP's code under specs, tests, and reviews.

1 The Models I Actually Use

Asynchronous work like daily summaries and analysis, where quality matters more than latency — roughly 4% of traffic.

2 The Cascading Strategy

Frontier quality for everything is a margin killer. So traffic cascades by value:

  • A self-hosted small model handles ~96% of traffic — pennies per call, no vendor lock-in.
  • A premium async model handles the ~4% where quality pays: summaries and analysis.

The break-even math: a $4.99 per-group pass against $0.30–0.50 of AI cost per group per tournament. The cascading is what makes 90%+ margins possible at consumer prices.

3 Cost Engineering

  • Free tiers as a product decision: the ERP runs every inference at $0 — document reading, setup suggestions, payment-batch composition — on free-tier inference providers.
  • Unit economics per feature: ~$0.02 per daily payment batch; ~$0.01 per month-end analysis. Small numbers, tracked honestly.
  • Funded targets vs. MVP reality: full-scale figures are goals for after revenue; the MVP lives inside free-tier limits by design.
  • Provider abstraction: OpenAI-compatible endpoints and an inference adapter layer so models can be swapped without code changes.

4 Agentic Coding in Practice

The ERP's codebase is being implemented by AI agents — 36 of 46 planned work items so far — under human-owned product decisions.

  • Specs first: every work item starts from a written requirement with acceptance criteria.
  • Test-first: tests define "done" before implementation starts.
  • Three independent reviews per change: blind, edge-case, and acceptance.
  • Humans own: scope, priorities, framing, and every acceptance decision.

5 What I Learned

  • Latency is a product feature. The chatbot's real-time feel comes from inference speed, not raw model size.
  • Some decisions should never be AI. The ERP's invoice matching is deliberately rules-based and auditable — AI extracts and suggests; deterministic logic decides.
  • Free tiers change product economics. Per-invoice AI cost is what makes competing tools expensive; free-tier inference removes it.
  • Models are swappable. Architecture should depend on capabilities and interfaces, not on one provider's name.
